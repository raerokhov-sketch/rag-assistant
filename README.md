# RAG-ассистент


## Структура

```text
rag-assistant/
├── data/
│   ├── raw/                 # исходные документы для индексации
│   └── processed/           # подготовленные данные
├── evaluation/
│   └── datasets/            # вопросы и эталонные ответы для оценки
├── src/
│   └── rag_assistant/
│       ├── chunking.py      # разбиение документов на фрагменты
│       ├── cache.py         # SQLite-кеш готовых ответов
│       ├── config.py        # настройки и переменные окружения
│       ├── generation.py    # формирование ответа по найденному контексту
│       ├── ingestion.py     # загрузка и индексация документов
│       ├── pipeline.py      # полный цикл RAG
│       ├── retrieval.py     # поиск релевантных фрагментов
│       ├── vector_store.py  # подключение к ChromaDB и получение эмбеддингов
│       └── __main__.py      # CLI для отдельных режимов и всего приложения
├── storage/
│   └── chroma/              # локальное хранилище ChromaDB
├── tests/
├── evaluation/evaluate_rag.py
├── pyproject.toml
├── requirements.txt
└── .env.example
```

## Запуск компонентов

Проект рассчитан на Python 3.12. Создайте виртуальное окружение и установите
зависимости из корня проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -e .
```

Запускайте любой компонент отдельно из корня проекта:

```powershell
python -m rag_assistant cache
python -m rag_assistant chunking
python -m rag_assistant assistant
python -m rag_assistant ragas
python -m rag_assistant ingest
```

Без аргумента или с режимом `all` открывается общее меню со всеми компонентами:

```powershell
python -m rag_assistant
# или
python -m rag_assistant all
```

Для вопросов ассистенту и оценки RAGAS сначала проиндексируйте документы через
режим `ingest` (или положите поддерживаемые документы в `data/raw` и выберите
индексацию в общем меню). Режим `cache` позволяет искать ответы и очищать кеш.
При запуске, по команде `stats` и перед выходом он показывает число записей,
попадания и промахи за текущий запуск, долю попаданий и размер файла базы данных.
Режим `chunking` читает готовые документы из `data/raw` и показывает чанки для
каждого файла; поддерживаются `.txt`, `.md` и `.markdown`, включая вложенные
папки.

## Оценка RAGAS

Режим `ragas` готовит данные `question`, `answer`, `contexts`, `ground_truth`,
получает ответы и контекст через основной RAG-пайплайн и оценивает их метриками
**Faithfulness**, **Answer Relevancy** и **Context Precision**. Модели оценки
используют тот же ProxyAPI endpoint и настройки моделей, что и основной RAG.

Загрузка документов в ChromaDB, семантический поиск и полный RAG-пайплайн
реализованы. `pipeline.answer_question` сначала проверяет SQLite-кеш, затем
ищет контекст в ChromaDB, вызывает chat-модель через настроенный API и сохраняет
ответ в кеш. Если контекст не найден, возвращается сообщение об отсутствии
информации без вызова модели; такой ответ не кешируется.

## Индексация документов

Поместите UTF-8 документы `.txt`, `.md` или `.markdown` в `data/raw` и запустите
из корня проекта в PowerShell:

```powershell
python -m rag_assistant.ingestion
```

Команда `python -m rag_assistant chunking` выводит разбиение этих же документов
на чанки без обращения к API. Индексация разбивает текст по пустым строкам, а
длинные абзацы — по предложениям.
Размеры чанков задаются в символах: минимум 100, максимум 500, overlap около 100
символов. Небольшие остаточные чанки могут быть короче минимума, если их нельзя
объединить с соседним без превышения максимума. Предложение длиннее максимума
сохраняется целиком. Эмбеддинги создаются моделью из `EMBEDDING_MODEL` через
настроенный OpenAI-совместимый endpoint и сохраняются в локальную коллекцию
ChromaDB `documents` в `storage/chroma`. При повторной индексации обновлённые
чанки заменяются, устаревшие удаляются.
Для уже проиндексированного файла проверяется SHA-256 содержимого: если файл с
тем же относительным путём не изменился, его чанки и повторный запрос эмбеддингов
пропускаются. Если файл изменён, его чанки обновляются.

Семантический поиск можно вызвать из кода:

```python
from rag_assistant.retrieval import search_documents

matches = search_documents("Как работает векторный поиск?", top_k=4)
```

Индексация обращается к API эмбеддингов и требует настроенный `OPENAI_API_KEY`.
Исходные документы и локальная база ChromaDB не добавляются в Git.

## Кеш ответов

Ответы хранятся в `storage/cache/answers.sqlite3`. При повторном вопросе с тем
же текстом (различия в пробелах игнорируются) пайплайн возвращает сохранённый
ответ без обращения к поиску и модели. Изменение регистра или формулировки
считается новым вопросом. Файл содержит вопросы и ответы в незашифрованном виде,
поэтому он добавлен в `.gitignore`. После обновления документов кеш следует очистить:

```python
from rag_assistant.cache import SQLiteAnswerCache

SQLiteAnswerCache().clear()
```

Вызов основного пайплайна:

```python
from rag_assistant.pipeline import answer_question

answer = answer_question("Как работает векторный поиск?")
```

## Настройка окружения

Скопируйте `.env.example` в `.env` и задайте в нём параметры ProxyAPI и моделей.
Приложение загружает настройки из `.env` и использует OpenAI-совместимый API
ProxyAPI для запросов к языковой модели. Ключ не хранится в исходном коде.
Не помещайте `.env` и исходные документы в систему контроля версий.

| Переменная | Назначение |
| --- | --- |
| `OPENAI_API_KEY` | API-ключ ProxyAPI |
| `OPENAI_BASE_URL` | OpenAI-совместимый endpoint ProxyAPI |
| `CHAT_MODEL` | Модель для генерации ответов |
| `EMBEDDING_MODEL` | Модель для эмбеддингов |
| `CHAT_TEMPERATURE` | Температура генерации |

Для ответа на вопрос одновременно необходимы непустая коллекция ChromaDB и
доступ к API эмбеддингов и chat-модели.

Зависимости включают совместимые с Python 3.12 версии RAGAS и LangChain:

```powershell
python -m pip install -r requirements.txt
```
